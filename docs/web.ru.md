# Веб-панель: подробная инструкция

[Краткое описание и установка](../README.md)


Панель управляет TCP/UDP-перенаправлениями: создание, редактирование, включение,
выключение и удаление правил. Наружу опубликован только HTTPS-порт nginx.
Логин фиксирован: `admin`. Установщик открывает меню установки, обновления,
смены режима и удаления. Пароль спрашивается только при первой установке;
при обновлении, миграции и восстановлении пароль и правила сохраняются.
Пароль — от 12 символов до 72 байт; хеш — bcrypt.

Установка на Debian/Ubuntu выполняется одной командой:

```bash
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/naum-mm/kaskad/main/install.sh | sudo bash
```

Запускайте на Linux-сервере, который будет пересылать трафик, с root-доступом,
Docker Engine и iptables/nftables. Установщик устанавливает отсутствующий Docker
и Compose из подписанных репозиториев дистрибутива. Rootless Docker и Docker Desktop
для управления firewall Linux-хоста не поддерживаются. Контейнер worker требует
`CAP_NET_ADMIN`; привилегированный режим и Docker socket ему не нужны.

Откройте `https://IP-сервера:ПОРТ`. Установщик генерирует самоподписанный сертификат
на 365 дней и выводит SHA-256-отпечаток. Сверьте отпечаток, затем добавьте сертификат
`/opt/go-kaskad/config/tls/server.crt` в доверенные. При доступе через публичный IP
за NAT или своё DNS-имя замените сертификат на подходящий для этого адреса.
TLS-файлы можно заменить без изменения пароля/порта; затем перезапустите nginx.
Установщик не меняет UFW/security groups: при необходимости разрешите выбранный
порт панели и порты правил в firewall провайдера.

### Меню и режимы

Перед выбором выводятся текущая установка и её метаданные, слушающие TCP/UDP-порты,
процессы, контейнеры Docker и работающие веб-сервисы. Выход не скачивает код
и не устанавливает пакеты.

1. **Отдельная установка:** свободный HTTPS-порт, self-signed или Certbot + домен.
   По умолчанию 8443 для self-signed и 443 для Certbot. Для Certbot standalone
   дополнительно нужен свободный и доступный снаружи TCP 80.
2. **Существующий nginx / SNI:** домен на общем 443, self-signed или Certbot.
   Домен нужен в обоих случаях. Локальный порт выбирается автоматически.
3. **Установленный Kaskad:** обновить код; пересоздать контейнеры с сохранением
   данных; обновить и изменить режим, порт и сертификат. Старый код перед
   сменой режима обновляется автоматически.
4. **Удаление:** сохранить настройки и правила для восстановления либо удалить
   проект полностью. Для полного удаления требуется ввести `DELETE`.

Конфликт с работающим сервисом или активным правилом форварда останавливает
операцию: чужие порты и сайты не перехватываются. Перед обновлением и сменой режима
сохраняются конфигурация, сертификат и согласованный снимок SQLite в
`/root/gokaskad-backups`. При ошибке скрипт пытается вернуть предыдущую конфигурацию;
ошибка восстановления показывается явно, резервная копия остаётся.

### Домен в существующем nginx

Поддерживаются nginx на хосте с `include /etc/nginx/conf.d/*.conf` и Docker nginx
с таким же include, bind mount каталога conf.d либо одного загруженного .conf,
ACME webroot, `/etc/letsencrypt:/etc/letsencrypt`, пользовательской сетью и портами
80/443. Неизвестные proxy и конфликтующие домены не переписываются. Внешний
HAProxy автоматически не настраивается; MASQUE — отдельная установка.

```text
Браузер → существующий nginx :443 (SNI / server_name)
             ├── существующие сайты
             └── домен панели → nginx Kaskad (HTTPS + пароль) → GUI / API
```

Только nginx панели подключается к сети существующего сайта. API остаётся в
`control`, SQLite не получает сетевого порта. Панель на хосте привязана к loopback;
TCP 80/443 зарезервированы от перенаправлений. TLS между nginx проверяет имя и
цепочку с `proxy_ssl_verify_depth 3`; для self-signed доверенным является конкретный
сертификат панели. Проверка TLS не отключается.

Self-signed действует 365 дней и требует проверки отпечатка / явного доверия в
браузере. Для обновления истекающего сертификата выберите пункт 3 → смена режима
и нужный тип сертификата. Действующий подходящий self-signed сохраняется.

Certbot запускается на хосте: его hooks видят проекты и Docker. Чтобы не задавать
дополнительных вопросов, установщик принимает условия Let’s Encrypt и создаёт
новую учётную запись без email. Нужны правильные DNS A/AAAA и доступный TCP 80.
Отдельный режим использует standalone HTTP-01; SNI использует существующий webroot.
При смене режима проверяется и при необходимости исправляется plugin/webroot
для продления. Используется существующий таймер либо включается `certbot.timer`.
Свой deploy hook обновляет сертификат панели и перезагружает nginx; чужие hooks
не заменяются.

Блок nginx помечен маркерами GOKASKAD. Single-file bind mount редактируется на
месте, без смены inode. После `nginx -t` выполняются reload и повторные HTTPS-проверки,
включая ожидание смены старого сертификата после асинхронной перезагрузки.
Служебный stdin Docker изолирован от кода `curl | bash` / heredoc.

### Удаление и восстановление

Пункт 4 → **сохранить настройки** удаляет контейнеры, свой домен/hook и правила
firewall, но оставляет `/opt/go-kaskad/config`, сохранённые параметры, сертификаты
и volume БД. Дополнительная копия SQLite сохраняется в `/opt/go-kaskad/saved`.
При следующей установке через пункт 1 или 2 пароль и правила используются повторно.
Не удаляйте volume БД через Docker prune, если планируете восстановление.

**Полное удаление** удаляет свои контейнеры, volume, файлы, домен/hook, ненужные
собственные сертификаты и добавленные неиспользуемые пакеты. Общий Docker и пакеты,
нужные другим проектам, сохраняются. Чужие сайты, сети, firewall и используемые ими
сертификаты не удаляются. У старой установки без манифеста состав общих пакетов не
угадывается. Отдельные резервные копии в `/root/gokaskad-backups` остаются; удаляйте
их вручную, когда они больше не нужны.

### Автоматизация и совместимость

Флаги: `--update`, `--reinstall`, `--change-mode`, `--keep-config`, `--purge`, `--menu`.
Удаление требует подтверждения; `GOKASKAD_CONFIRM=YES` явно передаёт его в автоматизации.
Для новой установки без меню: `GOKASKAD_ACTION=install`, `INSTALL_MODE=standalone|proxy`,
`CERT_TYPE=selfsigned|certbot`, `PANEL_DOMAIN` при необходимости, `MANAGEMENT_PORT`
и `ADMIN_PASSWORD`. Пароль не передаётся в argv и не хранится в .env: для передачи
дочернему установщику используется временный файл, доступный только root.

Старые команды `--configure-domain` и `--resume-domain` сохранены для прежних
установок и незавершённой настройки домена через Certbot. Для новых миграций
используйте пункт 3: ручное обновление перед сменой режима больше не нужно.
Ранее подключённый вручную proxy без манифеста можно обновлять; автоматическая
смена режима останавливается для проверки ручных настроек.

### Устройство

```text
Браузер → nginx :выбранный_порт (HTTPS + Basic Auth)
               ├── GUI (статические HTML/CSS/JS)
               └── API (внутренняя Docker-сеть)
                     └── Unix socket → worker → gokaskad.sh --machine → iptables
                                          └── SQLite (Docker volume)
```

Четыре контейнера: `nginx`, `gui`, `api`, `worker`. У API нет опубликованных портов;
сеть `control` изолирована от внешней сети. Worker использует сеть хоста, чтобы
менять его NAT, но **не слушает TCP/UDP** — только Unix-сокет. SQLite не является
сетевым сервисом и хранится в `gokaskad_worker-data`; доступа из API к файлу БД нет.
Пароль хранится только в виде хеша nginx, не в `.env` и не в БД. Basic Auth закрывает
как GUI, так и `/api/`; изменяющие запросы дополнительно требуют заголовок и проверку
Origin. Браузер запоминает Basic Auth до закрытия сессии браузера.

Правила панели используют собственные цепочки `GK_DNAT`, `GK_SNAT`, `GK_FORWARD`
и зарезервированную conntrack-маску `0x4b530000/0xffff0000`. Другие цепочки не
очищаются. Панель редактирует только свои правила; существующие правила старого
интерактивного CLI автоматически не импортируются. Не используйте старый
`--flush` одновременно с панелью: он очищает firewall целиком. Назначение — unicast
IPv4, не loopback; выбранный порт панели нельзя использовать как входящий порт
правила. Совпадения активных правил по протоколу и входящему порту запрещены.
Изменения влияют на новые соединения; существующие conntrack-сессии могут
продолжаться до завершения/таймаута.

Worker последовательно применяет изменения, затем сохраняет их в SQLite. При
ошибке выполняется восстановление предыдущих правил, запрос возвращает ошибку.
При старте worker восстанавливает правила из БД. Включение IP forwarding сохраняется
в `/etc/sysctl.d/90-gokaskad.conf`; BBR и глобальные firewall-политики установщик
не меняет. После перезапуска Docker при изменении его цепочек перезапустите worker,
чтобы проверить/восстановить переходы в цепочки Kaskad.

### Управление и данные

```bash
cd /opt/go-kaskad/current
sudo docker compose ps
sudo docker compose logs -f --tail=100
sudo docker compose restart worker
```

Настройки nginx и сертификат: `/opt/go-kaskad/config`. Порт, путь к настройкам и
автоматически выбранный backend iptables (nft/legacy):
`/opt/go-kaskad/current/.env`. База: `rules.sqlite3` в volume `gokaskad_worker-data`.
Для резервной копии остановите worker, скопируйте volume и каталог config, затем
запустите worker. `docker compose down` сохраняет volume и уже применённые NAT-правила;
для удаления перенаправлений сначала удалите правила через панель. `down -v`
удаляет БД без возможности восстановления — не используйте для обычного обновления.

Для обычного обновления выберите пункт 3 меню или `--update`. При ручном обновлении
разместите новый checkout/архив в отдельном каталоге `/opt/go-kaskad/releases`,
скопируйте `.env` из `current`, выполните там `docker compose up -d --build --wait`
и после проверки переключите симлинк `current`. Compose project name и volumes
остаются прежними; заранее сделайте резервную копию. Сертификаты обновляются отдельно.

### Обновление до v1.0.0 — Каскад

Новое название проекта — «Каскад» / Kaskad. Репозиторий переименован в
[`naum-mm/kaskad`](https://github.com/naum-mm/kaskad). Панель показывает версию
`v1.0.0`; функциональность и формат базы правил сохраняются.

На сервере с существующей установкой выполните:

```bash
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/naum-mm/kaskad/main/install.sh | sudo bash -s -- --update
```

Команда устанавливает актуальный `main`, сохраняет пароль, правила, порт,
сертификаты и режим доступа. Перед обновлением создаётся согласованная копия БД
и конфигурации в `/root/gokaskad-backups`; сохраните путь из вывода установщика.
При пересоздании сервисов возможен краткий перерыв перенаправлений.

**Переименование не требует перемещения файлов и volumes.** Для новой и существующей
установки по-прежнему используются `/opt/go-kaskad`, Compose project `gokaskad`,
volume БД `gokaskad_worker-data`, CLI `gokaskad.sh`, переменные `GOKASKAD_*`,
сокет `/run/gokaskad/worker.sock` и существующие цепочки firewall/маркеры nginx.
Это сохранённые технические имена для совместимости. Не переименовывайте их вручную,
не меняйте Compose project name и не выполняйте `docker compose down -v`.
Новые переменные `.env` и миграция SQLite не нужны.

После успешного обновления проверьте сервисы:

```bash
cd /opt/go-kaskad/current
sudo docker compose ps
sudo docker compose exec -T nginx nginx -t
```

API и worker должны быть `healthy`, nginx — пройти проверку. Откройте прежний
адрес панели, выполните `Ctrl+Shift+R` (`Cmd+Shift+R` на Mac) и проверьте название
KASKAD, версию `v1.0.0`, подключение worker, сохранённые правила и действующие
перенаправления. После смены названия области HTTP-аутентификации браузер может
повторно запросить прежние логин `admin` и пароль.

Если обновление завершилось ошибкой, установщик пытается запустить предыдущий
release. Сохраните резервную копию и предыдущий release; проверьте вывод и логи:

```bash
cd /opt/go-kaskad/current
sudo docker compose logs --tail=100 nginx gui api worker
```

Для локального Git checkout обновите remote после переименования:

```bash
git remote set-url origin git@github.com:naum-mm/kaskad.git
git fetch origin --tags
```

### Полное обновление

Рекомендуется пункт 3 меню или команда без дополнительных вопросов:

```bash
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/naum-mm/kaskad/main/install.sh | sudo bash -s -- --update
```

Она сохраняет текущий режим, делает резервную копию БД и при неудаче пытается
вернуть предыдущий release. Ниже оставлен ручной вариант для администратора.

В блоках `bash <<'UPDATE'` все неинтерактивные команды Docker запускаются с
`</dev/null`: иначе `docker compose exec -T` может прочитать оставшиеся строки
скрипта, и переключение `current` не выполнится. Установщик и удаление также
изолируют stdin служебных команд от кода, переданного через `curl | bash`.

Для блока «Системный firewall» нужно обновить **GUI, API и worker**: замены только
HTML/CSS недостаточно. Существующий пароль, порт, сертификат и volume БД используются
повторно. Полное обновление из `main` на сервере:

```bash
sudo bash <<'UPDATE'
set -euo pipefail
root=/opt/go-kaskad
test -f "$root/current/.env"
release=$(mktemp -d "$root/releases/update.XXXXXX")
curl --proto '=https' --tlsv1.2 -fsSL https://codeload.github.com/naum-mm/kaskad/tar.gz/refs/heads/main |
  tar -xz --strip-components=1 -C "$release"
cp -p "$root/current/.env" "$release/.env"
if [ -f "$root/config/proxy.json" ]; then
  install -m 600 "$release/tools/proxy_setup.py" "$root/config/proxy_setup.py"
fi
cd "$release"
docker compose config --quiet </dev/null
docker compose up -d --build --wait --wait-timeout 180 </dev/null
docker compose exec -T nginx nginx -t </dev/null
ln -sfnT "$release" "$root/current"
UPDATE
```

Системный firewall показывается отдельно и только для чтения: iptables-nft,
iptables-legacy, IPv4/IPv6 и отдельные цепочки nftables, включая fail2ban. Наборы
адресов nftables раскрываются в таблице; при ошибке чтения видна отметка неполного
обзора. Это снимок правил ядра, а не статус процесса fail2ban или список его настроек.

### JSON CLI для worker

Интерактивный CLI продолжает работать. Дополнительный машинный режим используется
в контейнере worker (Python 3, `STATE_DIR`, `MANAGEMENT_PORT`):

```bash
docker compose exec -T worker bash /app/gokaskad.sh --machine list
printf '%s\n' '{"id":"b29bc2cf-47c6-43bc-8e49-5d560378fe66","name":"web","protocol":"tcp","input_port":8080,"target_ip":"192.0.2.10","target_port":80,"enabled":true}' |
  docker compose exec -T worker bash /app/gokaskad.sh --machine put
```

Ответы — JSON; код 0 означает успех, 2 — неверный запрос, 1 — ошибку firewall/БД.
`delete` принимает `{"id":"UUID"}`, `reconcile` восстанавливает правила из БД.
`firewall` возвращает системные цепочки и правила, ничего не изменяя; API использует
для него только `GET /api/firewall`.

### Разработка и проверки

```bash
python3 -m unittest discover -s tests -v
bash -n gokaskad.sh install.sh
node --check web/gui/app.js
```

Для Docker-проверок нужен Linux Docker Engine. Реальный NAT проверяется в отдельном
сетевом namespace worker через override `network_mode: bridge`, чтобы не менять
firewall машины разработки. Production-конфигурация использует `network_mode: host`.

Интеграционный сценарий: подготовьте тестовые `admin.htpasswd` и TLS-файлы в
`CONFIG_DIR`, задайте `MANAGEMENT_PORT=18443`, затем:

```bash
docker compose -p gokaskad-test -f compose.yaml -f tests/compose.smoke.yaml up -d --build --wait
SMOKE_PASSWORD='<тестовый пароль>' SMOKE_CA="$CONFIG_DIR/tls/server.crt" python3 tests/docker_smoke.py
# Опционально, при установленном Playwright:
SMOKE_PASSWORD='<тестовый пароль>' node tests/browser.cjs
docker compose -p gokaskad-test -f compose.yaml -f tests/compose.smoke.yaml down -v
```

`tests/docker_smoke.py` отказывается работать с worker в сети хоста. Проверяются
настоящие TCP/UDP-запросы, HTTPS/аутентификация, CSRF, восстановление после рестарта,
отключение правил и отсутствие опубликованных портов внутренних сервисов.
GitHub Actions выполняет этот сценарий автоматически; browser-тест дополнительно
проверяет создание, редактирование, отключение, удаление правил и мобильную вёрстку.
